# ai-collab — AI 协作体系：把 AI 助手管成一个 4 人团队

> 一套经过多项目实战验证的**人机协作治理方案**：通用角色全局共享、项目差异本地化、红线划清人机边界。
> 核心一句话：**一套角色全局共享 + 每个项目的差异交给各项目自己的 rules。**

## 它解决什么问题

在多项目 × 多 AI 工具环境里，AI 协作角色（subagent）没有统一治理时，会出三类典型问题：

| 问题 | 表现 | 后果 |
|---|---|---|
| 角色资产重复建、各自漂移 | 每个项目复制一份角色文件，改法不一 | 同一角色在 A 项目能用、B 项目失灵 |
| 角色与项目知识耦合 | 角色提示词里写死项目术语、接口、路径 | 换个项目就不能用，无法复用 |
| 平台机制不清就设计 | 按直觉设计专属角色，实际不生效 | 返工、删资产、多走一轮登记 |

## 三条可复用原则

1. **角色与知识解耦**：角色文件只写通用能力与规则，不写死任何项目数据、术语、接口；项目差异一律放该项目 rules。收益：角色资产跨项目零修改复用。
2. **全局共享 + 差异本地化**：一套通用角色所有项目共享；每个项目通过自己的 rules 注入差异。收益：维护成本 O(N) 降到 O(1)，新项目 15 分钟接入。
3. **机制先验证**：新平台能力落地第一步，先实测平台机制（能否自动识别、角色作用域、字段映射规则），再设计资产。**文件就位 ≠ 生效**。

## 通用 4 角色体系

| 角色 | @ 标识 | 职责 | 典型调用时机 |
|---|---|---|---|
| 架构分析师 | `@architect` | 方案设计、技术选型、结构评审；开工先读该项目 rules 建立认知 | 新任务开始、跨模块改造前 |
| 独立代码审查官 | `@code-reviewer` | 只读审查出 P0/P1/P2 问题清单，**绝不改代码**（无自我辩护倾向） | 代码提交、联调前 |
| 文档管家 | `@doc-keeper` | 维护 docs 索引、开发日志、文档结构体检 | 文档沉淀、索引更新 |
| 需求澄清官 | `@requirement-clarifier` | 把模糊需求问成可开发规格（每问附建议答案） | 接需求、写计划前 |

设计要点：**写代码的 AI 不审查自己的代码**——code-reviewer 独立编制、禁用 Edit、只读审查，从机制上消除"自己查自己"的利益冲突。

## 资产地图

| 路径 | 内容 |
|---|---|
| [`roles/`](roles/) | 通用 4 角色（Trae subagent 格式，可直接加载；可迁移到其他支持 subagent 的 AI IDE） |
| [`templates/`](templates/) | 项目 rules 骨架模板（占位符替换即用）+ 工作风格节通用模板 |
| [`sop/project-onboarding.md`](sop/project-onboarding.md) | 新项目接入 SOP（约 15 分钟，5 步） |
| [`sop/code-review.md`](sop/code-review.md) | 代码审查 SOP：七步流程 + 六维框架 + P0-P3 分级 |
| [`red-lines.md`](red-lines.md) | 人机边界红线：开发铁律 7 条 + 维护演进红线 4 条 |
| [`scripts/install.sh`](scripts/install.sh) | 一键接入新项目（目录 + 角色 + rules 节） |
| [`scripts/check_roles.py`](scripts/check_roles.py) | 角色资产静态校验：frontmatter 完整性 + 写作纪律 + **泄漏扫描**（拦截公司信息进入公开仓库） |

## 快速开始

```bash
# 方式一：一键接入（Step 1-3 自动完成）
bash ai-collab/scripts/install.sh /path/to/your/project

# 方式二：照 SOP 手动接入（约 15 分钟）
# 见 sop/project-onboarding.md，可把该文件直接丢给 AI 执行

# 提交前自检：泄漏扫描 + 角色纪律校验
python ai-collab/scripts/check_roles.py --ci
```

## 实战效果（截至成稿）

- 3 个并行项目接入同一套 4 角色，零修改复用；新项目接入约 15 分钟
- 独立审查机制拦截多起 AI 交付缺陷：越层读写只读系统、幂等缺失、单位口径不一致等，问题全部以「文件:行号」定位
- `check_roles.py` 的泄漏扫描作为提交前 CI 关卡，防止内部信息误入公开仓库
