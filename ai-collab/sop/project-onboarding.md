# 新项目接入 SOP（约 15 分钟）

> 适用：任何新项目接入本 AI 协作体系。做完后 AI 在该项目内自动具备：规则约束 + 架构分析 + 独立审查 + 文档管家 + 需求澄清。
> 也可以把本 SOP 直接丢给 AI：「读这个文件按它执行」。

## Step 0 · 前置确认（1 分钟）
- [ ] 新项目代码已在本地，确定工作区根路径（记为 `<工作区>`）
- [ ] 确定该项目「只读目录」有哪些（原系统/旧代码/生产副本）——没有则为空
- [ ] 确定需求文档放哪（没有可先跳过，注明"待补"）

## Step 1 · 建目录结构（1 分钟）
在 `<工作区>` 下创建：
```
.trae/
├── rules/
│   └── user_rules.md      ← 项目规则（Step 2）
└── agents/                ← Subagent（Step 3）
docs/                      ← 文档唯一落盘根（如项目已有约定目录名则用约定名）
```

## Step 2 · 写项目规则（5 分钟）
1. 复制 `templates/user-rules-template.md` → `<工作区>/.trae/rules/user_rules.md`
2. 逐项替换 `<尖括号>` 占位符：项目名 / 代码位置 / 目录结构 / 技术栈 / 核心决策 / 只读目录 / 文档根 / 进度 / 环境信息
3. 末尾「工作风格与协作规范」节**保留原样**（统一标准段）
4. 敏感信息（密码/密钥）不写明文，写"见配置文件"

## Step 3 · 放 Subagent（1 分钟）
复制 `roles/` 下 4 个文件到 `<工作区>/.trae/agents/`：
- architect.md（架构分析师）
- code-reviewer.md（独立审查官）
- doc-keeper.md（文档管家）
- requirement-clarifier.md（需求澄清官）

> 一键方式：`bash scripts/install.sh <工作区>`（自动完成 Step 1-3 + rules 节追加）。

## Step 4 · 登记与全局记忆（1 分钟）
1. 打开 AI IDE 的「创建智能体」UI，按各角色 frontmatter 手动登记（多数平台不自动扫描，必须登记一次）：
   - 名称 = 角色中文名；英文标识 = frontmatter `name`；何时调用 = `description`；提示词 = 正文全文
2. 全局偏好（如回复格式、汇报习惯）粘到平台「全局记忆 / User Rules」一次，所有项目生效

## Step 5 · 验证（2 分钟）
1. 重启窗口 / 新建对话（让 rules 与 subagent 生效）
2. 测试：对话里发「@code-reviewer 读一下项目 rules 并列出待审文件清单」→ 应能识别并工作
3. 让 AI 先通读 rules 汇报理解，确认没有理解偏差再开工

## 每次新项目必查的 4 个问题
1. 只读目录写清楚了吗？（AI 误改原系统的最大原因就是 rules 没写）
2. 文档根目录定了吗？默认 docs/，若项目已存在约定目录用约定名
3. 生产/线上有没有？（有则 rules 里必须写"改前 git 备份"红线）
4. 数据库方言 / 部署目标确认了吗？（开发期与部署期可能不同，写进核心决策）

## 机制先验证（重要经验）
文件就位 ≠ 生效。新平台接入时，先实测三件事再设计资产：
1. 平台能否自动识别 `.trae/agents/`（或对应目录）的角色文件
2. 角色作用域是全局还是项目级
3. UI 登记字段与 md 字段的映射规则
一切以实测结果为准，避免"资产建好了却不生效"的返工。
