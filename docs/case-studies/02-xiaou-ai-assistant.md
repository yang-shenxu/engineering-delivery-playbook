# Case Study 02 · 火电运维 AI 智能问答助手「小U同学」

> 定位：对外讲 AI 落地能力 + 现场交付能力（数据/AI 岗、FDE 岗核心弹药）
> 时间跨度：2026.05 – 2026.09（立项 → 私有化现场交付）

---

## 一句话摘要

在"生产后端零代码变更、现场内网隔离、无 GPU 支撑本地大模型"三重约束下，独立完成 AI 问答产品从需求梳理、架构设计、AI 编排、提示词工程到测试验收的全链路，并以"微主机内网部署 + 在线模型 + 本地向量化"的混合形态打包交付现场，端到端问答现场验证可用。

---

## 1. 背景：一线运维人员为什么需要 AI 助手

火电机组运行参数数百项，运维人员日常要查实时值、越限告警、能耗报表、寻优结果，还要结合设备知识库做判断。数据分散在多个系统，想拿到"一个参数 + 调整建议"要跨系统多次操作。

目标很朴素：让一线人员"用一句话问到数据 + 建议"。

## 2. 三重约束（决定方案形态）

| 约束 | 影响 |
|---|---|
| 生产后端零代码变更 | AI 层只能做 HTTP 调用，不能改生产配置 |
| 现场内网隔离 | 无法访问外部服务器，AI 服务必须搬到现场 |
| 现场无 GPU | 本地大模型跑不动，但数据又不允许出网 |

**架构决策**：内网部署 + 在线模型——Dify 放微主机内网，大模型走专属在线模型通道（解决无 GPU），Embedding 向量化本地运行（解决内网隔离）。

## 3. 解决方案：架构与四个关键决策

### 架构链路

```
浏览器 → Vue2 前端（悬浮窗 / 完整页）
  → Dify Agent（微主机内 docker-compose，开机自启）
    → 大模型：在线模型通道
    → Embedding：fastembed + bge-small-zh-v1.5（本地，512 维）
      → 4 个 Custom Tool（Swagger Schema 直连现场后端）
        → 现场后端（实时数据 / 报表 / 越限三个服务）
```

### 关键决策①：工具收敛 16 → 4

立项期接了 16 个只读接口，实测暴露核心问题：部分接口依赖数据库内部 ID，大模型无法自行推断正确值，返回空数据。据此收敛为 4 个通用工具：

1. `query_realtime_indicator` — 实时指标查询
2. `query_operation_adjustment_suggestions` — 运行调整建议（29 项因子）
3. `query_unit_model_list` — 模型库列表
4. `query_universal_report` — 通用报表问答

其中"通用报表"以**单一接口 + URL 路径区分**覆盖 20+ 业务报表，新报表接入成本从"改代码"降为"加一行提示词"。

### 关键决策②：AI 代理微服务解耦

把 AI 代理逻辑从单体业务系统**物理拆分**为独立微服务（Spring Boot），以 HTTP 复用原有 7 个数据接口（连接/读取双超时），坚持"零后端代码变更"原则——只做调用层，避免改动生产配置引发连锁报错，显著降低部署耦合。

### 关键决策③：提示词工程 30+ 轮迭代

- 建立**工具选择优先级**规则（单指标实时值 vs 含建议指标 vs 混合场景），修复工具误调用（知识问答误触发数据查询、报表问题误调通用报表）；
- 建立**防幻觉铁律**（强制先查知识库、报表不做无依据异常判断、禁止输出引用标注）；
- 引入 Dify 代码节点 Python 脚本做数据清洗，解决"大模型无法可靠过滤异常值"；
- 反编译定位并修复鉴权有效期 bug：硬编码 15 分钟 → 365 天，并修正 int 溢出（原代码实际仅 17 天）问题。

### 关键决策④：现场部署工程化（内网 + 无 GPU 落地）

- 硬件：小米微主机（i5-1240P / 16GB / 512GB），双系统改装 Ubuntu Server 24.04 单系统；
- Dify 以 docker-compose 部署，restart policy 开机自启；
- Embedding 本地化：fastembed + bge-small-zh-v1.5，systemd 服务自启；
- 现场排障三个真实案例：
  1. 知识库创建 Internal Server Error → 根因消息队列密码未做 URL 编码，编码后恢复；
  2. Embedding 重启后不监听 → 三层根因（启动联网校验被墙、缓存落在易失目录、环境变量不生效），解法：缓存迁移持久目录 + 代码构造函数硬编码 cache_dir + 离线环境变量 + 服务依赖网络就绪；
  3. 模型下载 80% 报 Xet CAS 401 → 禁用 Xet 存储走普通 HTTPS 下载；
- 备份与应急：Dify 数据卷 + Embedding 模型资产 + 配置，三份备份同步 U 盘供现场应急恢复。

## 4. 量化结果（全部真实可追责）

| 维度 | 数值 |
|---|---|
| 提示词迭代 | 30+ 轮（封版） |
| 测试用例 | 100+ 条：实时指标 22/22、全量回归 24/24、端到端 10 条、知识库 10 条等 |
| 工具收敛 | 16 个只读接口 → 4 个通用工具 |
| 通用报表覆盖 | 单接口 + URL 路径覆盖 20+ 业务报表 |
| 新报表接入成本 | "改代码" → "加一行提示词" |
| 鉴权 bug 修复 | 15 分钟 → 365 天（原代码 int 溢出实际仅 17 天） |
| 知识库 | 12 份文档 / 186 页 |
| 现场验证 | 4 工具连通现场后端、端到端问答可用、前端已改连微主机 |

## 5. 方法论沉淀（可复用）

1. **约束驱动架构**：无 GPU → 在线模型通道；内网隔离 → 本地向量化；生产不可动 → 零后端代码变更。每个约束都对应一个明确的架构决策；
2. **工具收敛原则**：接口越多越不可控——先接 16 个暴露问题，再收敛 4 个通用工具 + 配置驱动，把"模型猜参数"变成"工具替模型拿参数"；
3. **离线部署三件套**：缓存迁移持久目录 + 离线环境变量 + 服务依赖网络就绪；
4. **环境变量不可靠时，代码硬编码传参最稳**；
5. **防幻觉三铁律**：必查知识库、工具选择优先级、报表不做无依据异常判断。

## 6. 角色与协作边界

- **独立负责**：项目立项、架构设计、微服务解耦、工具链与提示词工程、100+ 条测试体系、前端模块（Vue2 悬浮窗 + 完整页）、部署方案与交付手册；
- **协作边界**：后端零代码变更（仅 HTTP 调用）；微主机系统安装、网络配置、SSH 等现场动作由实施团队执行，我交付"逐步打勾的现场实施 Checklist + 部署运维与排错手册 + 交接待办"；
- **验收标准**：分阶段测试回归（22/22、24/24 全通过）+ 现场端到端问答验证可用。
