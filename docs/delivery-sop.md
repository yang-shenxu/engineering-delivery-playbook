# 项目交付流程 SOP（对外版 v1.0）

> **适用场景**：外挂式/适配层类项目、第三方系统对接、带硬截止的上线任务、生产数据只读、系统跑在客户资产上。
> **本 SOP 来源**：一次真实的市级生活服务平台「消费券抵扣」模块交付实践（从立项到全量上线，跨度约 4 周）。已去除客户方、合作方与环境的全部标识，保留可直接复用的方法与判据。
> **怎么用**：① 开工前按「第二章」逐阶段推进；② 每阶段交付前对照「准出判据」；③ 遇卡点查「第六章」；④ 写文档套用「第五章模板」。
> 落款：ysx · 2026-09-28

---

## 〇、一页速览

| 项 | 内容 |
|---|---|
| **交付形态** | 独立外挂服务 + 独立入口，**不改动被对接系统的源码**；按业务规则扣减/结算，只向调用方回成败 |
| **五条项目特征** | ① 外挂不改原系统 ② 三方（或多方）对接 ③ **硬截止** ④ 生产库只读 ⑤ 运行在**客户资产**上 |
| **一句话方法论** | **先取证再结论、先模拟再生产、逐台部署逐台验、每步可回退、一切留痕（只增不删）** |
| **流程骨架** | **九步走 + 三道闸门 + 十条纪律 + 五类风险** |
| **交付判据（铁律）** | 看**技术指标**（通道可达 / 一笔打穿 / 金额守恒 / 幂等 / 受理成功率）；**"使用量"不进验收项** —— 系统上线与业务规模**解耦** |

## 一、总流程地图

### 1.1 项目类型特征 → 决定了流程怎么设计

| 特征 | 由此决定的流程要求 |
|---|---|
| **外挂式**（不改原系统） | 一切改动走**独立服务 + 独立入口**；原系统源码**只读** |
| **多方对接** | 必须建**角色边界**与**对外台账**；提问按渠道拆分 |
| **硬截止** | 必须设**闸门**与**降级触发条件**；截止后不引变更（只保留应急回滚） |
| **生产库只读** | 新数据一律放**自建库**；跨库取数走**导出/导入**，不直连改 |
| **跑在客户资产上** | 部署/重启必须**逐台**，避免全量中断；表述上明确归属 |

### 1.2 九阶段流程

```
S0 立项与角色定位
   ↓
S1 需求与口径收集 ──（口径确认单，客户确认）
   ↓
S2 现状勘察 ──（读码取证 + 方案对比 + 冲突预判）
   ↓
S3 契约与设计 ──（字段对照表 / 事务边界 / 回滚矩阵）
   ↓
S4 编码 ──（指令 → 交付 → 独立复核 → 修复指令 → 复核）
   ↓
S5 本地模拟验证 ──（mock 模拟生产 + 逐步验收）
   ↓
S6 部署与切换 ──（逐台 + 校验 + 软链 + 秒级回退）
   ↓
S7 联调 ──（作战手册 + 逐笔用例 + 异常预案）
   ↓
S8 上线与值守 ──（上线检查清单 + 回滚三级 + 台账）
   ↓
S9 运营期 ──（巡检 / 备份 / 定期同步 / 复盘）
```

### 1.3 三道闸门

| 闸门 | 时点 | 含义 | 未过的处置 |
|---|---|---|---|
| **决策门 A** | 开工前 | 关键口径已锁定（接口范围 / 计费规则 / 有效期等） | 不锁定不开工；残余问题以"我方默认口径 → 客户确认或否掉"方式收敛 |
| **就绪闸门 B** | 上线前最后一个可用工作日 | 部署完成 + 检查清单全过 + **一笔真实小额打穿** | **放弃本期放量**，提前报备，不硬上 |
| **放量闸门 C** | 正式放量日 | 试运行期异常清零 | 有异常 ⇒ 回滚到上一稳定态 |

> 🔴 **闸门设置必须同时算清"假期窗口"**：若截止日之后紧接着长假期且无值守，则**截止日前未完成的，最早要到复工后第一天才能动** —— 这会直接改变排期。

## 二、阶段 SOP

> 每阶段固定四要素：**目标 / 输入 / 动作 / 输出物 + 准出判据**

### S0 · 立项与角色定位

| 项 | 内容 |
|---|---|
| **目标** | 把"谁是谁、谁负责什么、边界在哪"钉死，避免全程返工 |
| **输入** | 委托关系、系统拓扑、账号权限 |
| **动作** | ① 列**角色表**（按"职责类型"而非人名）；② 定**称谓规则**；③ 划**红线**；④ 明确**协作分工** |
| **输出物** | 项目基线与边界文档 + 团队长期约定 |
| **准出判据** | 每个外部方**一句话能说清"找他做什么"**；红线成文 |

**角色按"职责类型"区分（示例）**

| 角色类型 | 只管什么 |
|---|---|
| **业务方（客户）** | 需求 + 验收 + 拍板 |
| **下游平台方** | 发起调用 / 切换地址 / 联调 / 现场执行 |
| **数据服务方** | 基础数据 / 数据接口 |
| **交付方（我方）** | 设计 + 开发 + 部署 + 运维 |

> 🔴 **称谓一旦定错 = 责任归属错**：把 A 方提供的数据记成 B 方给的，会直接导致错误追责。**称谓规则要写进文档，并在每次对外沟通前核对。**
> 🔴 **资产归属表述**：系统跑在客户账号下的机器上 ⇒ 对外统一说「**就在你们那台服务器上**」，不说"我们的服务器"。

**协作分工（验证高效的定式）**

| 环节 | 谁 | 做法 |
|---|---|---|
| 需求/口径 | 业务方拍板 | 分歧时给"我方默认口径"，让其确认或否掉 |
| 设计/方案 | 设计方 | 出设计/方案/指令/复核文档，**不写业务代码** |
| 编码 | 编码方 | 只写代码，**不打包/不部署/不启服务/不执行 SQL** |
| 复核 | 设计方 | **独立读码**，**不采信自述** |
| 验收/部署 | 交付负责人 | 按逐步操作单执行 |
| 留痕 | 设计方 | 台账、日报、索引、记忆 |

### S1 · 需求与口径收集

| 项 | 内容 |
|---|---|
| **目标** | 把"能确定的"确定下来，"不能确定的"变成**书面待确认项**，而不是留在口头 |
| **输入** | 业务需求、外部接口文档、旧系统行为 |
| **动作** | ① 收敛必问清单（**能不问就不问**）；② 出**口径确认单**；③ 问题按渠道拆分 |
| **输出物** | 口径确认单（一页、业务语言）+ 对外对接总台账（唯一视图）+ 待问清单 |
| **准出判据** | 每个待确认项有**明确归属人 + 期限**；关键口径已**书面确认** |

**关键做法**

1. 🔴 **非必要不提问** —— 能从**报文实样 / 读源码**得到的答案，**不占用对方时间**。
   *实例：原本准备向平台方确认"试点能否按场生效 / 报文是否含场地标识"，判读"联调首笔报文本身就是答案" ⇒ 对外提问数降为 0。*
2. 🔴 **提问按渠道拆分** —— 群聊（有客户与领导）**只问必要事项、只对时间**；**技术细节走一对一**。
3. 🔴 **口径确认单必须"业务语言"** —— 业务项（活动期/预算/比例/取整规则）用大白话一页列清；技术取值另起一节。**客户看得懂，才会签字。**
4. 🔴 **"默认口径 → 确认或否掉" 优于开放式提问**（闭式选择 ≫ 开放问答），能显著缩短一轮往返。

### S2 · 现状勘察（取证 + 冲突预判）

| 项 | 内容 |
|---|---|
| **目标** | 动手前看清"地上有什么、哪里会撞车" |
| **输入** | 被对接系统源码（只读）、服务器现状、证书/DNS/网关现状 |
| **动作** | ① 只读勘察；② **逐字读源码核对**；③ **列冲突**并给方案对比 |
| **输出物** | 冲突分析文档（含方案对比 + 待核实项）+ 勘察结论 |
| **准出判据** | **"待核实项"全部落实为实测结果**；方案已定并留痕 |

**两类必须勘察才发现的坑（真实案例）**

| 坑 | 发现方式 | 若不勘察的后果 |
|---|---|---|
| **路径冲突**：新服务端点与**被对接系统自身接口同域名同路径** | 读对方路由表 + 网关配置 | ① 对方既有接口全挂 ② **我方出站调用自噬**（转来转去转回自己）⇒ 最终改为**独立域名/独立入口** |
| **文档与实际不符**：对方真实接口数 **30+**，而给的文档只有 **16** | 读对方路由表 | 若按"文档白名单逐条放行"**必漏** ⇒ 改为**"除指定路径外全透传"** |

> 📌 **勘察纪律**：**先勘察、后动手**；勘察命令一律**只读**（`ls`/`cat`/网关配置导出/软链查看），**不改一个字节**。

### S3 · 契约与设计

| 项 | 内容 |
|---|---|
| **目标** | 把接口契约、字段映射、事务边界、回滚口径**写死**，让编码无歧义 |
| **输入** | 真实报文样例、对方源码、业务规则 |
| **动作** | ① 出**字段对照表**；② 出**事务边界总表**；③ 出**状态判定优先级**；④ 出**回滚矩阵** |
| **输出物** | 业务层设计 + 字段对照表 + 表设计 |
| **准出判据** | 编码方**照着文档能写、无需再问** |

**① 事务边界总表（最容易踩坑处）**

| 步骤 | 事务 | 失败处理 |
|---|---|---|
| 鉴权 / 幂等查重 | 无（只读） | 401 / 直接回上次结果 |
| 本地资源核销（券/额度） | **外层事务** | 抛异常整体回滚，不产生业务效果 |
| **外部扣款/结算调用** | 🔴 **独立事务（REQUIRES_NEW）** | 先落流水后调通道；未知状态留"待确认"交补偿任务 |
| 写业务记录 | 外层事务 | 与资源核销同生同死 |
| **附加动作（如返利/赠券）** | 🔴 **独立事务（提交后）** | **附加动作失败绝不复主交易** —— 用户已完成支付，不能因赠品失败而回滚 |
| 返回结果 | 无 | — |

> 🔴 **铁律**：**外部调用与附加动作绝不能放在外层事务** ⇒ 否则出现"外部已扣款、本地已回滚"的资金不一致。

**② 出站接口的「前置核对清单」（由 5 次真实事故换来）**

```
凡新增/修改「出站接口」，动手前必须拿对方源码逐字核对：
  □ 状态机      —— 返回状态的枚举与字段名（如 trade_status vs status）
  □ 唯一性约束  —— 单号是否全局唯一、是否"前置即占用"（先插单再调第三方）
  □ 返回键名    —— 业务文案在 data.message 还是 body.msg（🔴 判据一律看 data.*）
  □ 签名口径    —— 参与签名的字段集合 + 算法 + 值转换规则
  □ 同步改 mock —— mock 必须照对方实现，否则"mock 全绿、生产失效"
```

### S4 · 编码（指令 → 交付 → 独立复核）

| 项 | 内容 |
|---|---|
| **目标** | 让编码可追溯、可复核、可回退 |
| **输入** | S3 设计文档 |
| **动作** | ① 出**开发/修复指令**；② 编码方交付（含改动文件+行号+自检）；③ **独立读码复核**；④ 有缺陷 ⇒ 修复指令 ⇒ 再复核 |
| **输出物** | 指令 / 复核报告（成对存在） |
| **准出判据** | 复核**逐条通过**；红线守住；**遗留项已登记** |

**指令模板要点（缺一不可）**

- **项号 + 文件 + 行号 + 可粘贴代码 + 提交自检**（代码直接给，不用描述）
- 🔴 **红线清单**（不许动什么）
- 🔴 **计数类期望值必须声明口径**（含不含注释、含不含"只改注释"的文件）
- 🔴 **禁区**：不打包、不部署、不启服务、不执行 SQL、被对接系统源码只读

**复核纪律（不采信自述）**

| 动作 | 说明 |
|---|---|
| **逐条读码** | 按行号去文件里对，**不看它的描述** |
| **全项目检索取值点** | 同一个 bug 往往有**多个取值点**（本实践中有一次"第二轮才挖出同源第三处"） |
| **核对是否擅改期望值** | 最容易被糊弄的一处：**改不动代码就改测试期望值** ⇒ 复核方须**独立复算基线** |
| **越界面核对** | 有没有动不该动的文件 / 加依赖 |

> **实践效果**：这套复核在一个项目里挖出 **4 条**上线级缺陷，**全部是"本地全绿、生产失效"型**（详见第六章）。

### S5 · 本地模拟验证（模拟生产）

| 项 | 内容 |
|---|---|
| **目标** | **零触碰生产**地验证通道行为（含失败/超时路径） |
| **输入** | S3 设计 + 本地 mock |
| **动作** | ① 起本地 mock（同路径/同报文）；② 启动参数**覆盖全部出站地址**指向 mock；③ 逐用例**逐步验收** |
| **输出物** | 验收方案 + 验收记录（含原始证据） |
| **准出判据** | **硬判据全过**（金额守恒/回滚/幂等/签名通过…） |

**四条关键做法**

1. 🔴 **自建 mock 模拟被测系统**
   - 触发词放在**通道能原样看到的字段**里（因为出站单号常是**派生值**）
   - 🔴 **mock 必须照对方口径实现验签，且默认开启** —— 若默认关，签名错了也全绿
2. 🔴 **启动参数覆盖全部出站地址**（易漏的是"取令牌"那条 ⇒ 漏了会**去生产取 token**）
3. 🔴 **逐步验收（一次一个 Step）**：给"明确命令 + 期望值 + 回填格式"，做完再给下一步；**禁止一次性抛整套用例**
4. 🔴 **计数/状态类期望值先声明前提**（是否重启过、是否重置过数据、账号当前是否满足条件）否则必出"数字对不上的假问题"

**验收判据分两类**

| 类型 | 不过时 |
|---|---|
| 🔴 **硬判据**（金额守恒 / 状态回滚 / 不重复处理 / 签名通过 / 幂等） | **一项不过即停，不放行** |
| 🟡 **观察项** | 先分清是"功能没达标"还是"**期望值写错了**" |

> 📌 **改代码后先重启服务再跑用例** —— 否则跑的是**旧 class**。（本次实践中曾因此白绕一轮，最终靠"签名指纹（首 4 位 + 尾 2 位 + 长度）反推"定位。）

### S6 · 部署与切换

| 项 | 内容 |
|---|---|
| **目标** | 上新版本且**全程可回退**、**用户无感** |
| **输入** | 构建产物 + 部署操作单 |
| **动作** | ① 本地构建（**保留测试**）；② 上传 + **校验对拍**；③ 命名改造 + **软链切换**；④ **逐台**重启；⑤ **逐台验证** |
| **输出物** | 部署操作单（含回滚命令） |
| **准出判据** | **每台**验证通过；回滚命令**已验证可用** |

**六条铁律**

| # | 铁律 | 原因 |
|---|---|---|
| 1 | 🔴 **逐台切换，不同时重启两台** | 负载均衡会把流量导到另一台 ⇒ 用户无感 |
| 2 | 🔴 **上传后做哈希对拍** | 防上传截断/损坏 |
| 3 | 🔴 **产物命名 `名称-日期-短hash` + 固定软链** | 回滚 = 改软链，**秒级** |
| 4 | 🔴 **逐台验证要用"强制解析到本机"的方式** | 否则 DNS→负载均衡→又轮询回另一台，**测不到本台** |
| 5 | 🔴 **改动必须两台一致** | 曾因"只改一台"⇒ **一半请求 404**，且潜伏多日 |
| 6 | 🔴 **先部署产物 → 再改网关 → 验证 → 最后通知外部** | 顺序颠倒 ⇒ 要么功能未生效、要么让对方再撞一次 |

**"请求落到谁手里"的判据（可复用）**

| 谁返回 | 怎么认 |
|---|---|
| 自有服务 | JSON（含框架特征字段），**无**对方平台特有的响应头 |
| 对方系统 | 带其平台标识响应头（如 `X-Powered-By: PHP`） |
| 网关 | 网关自身的 HTML 错误页 |

> 🔴 **多节点后端，验证必须"逐节点做"** —— 本次实践中两次验证都从同一台发请求 ⇒ 另一台**从未被验到**，隐患潜伏 4 天。

### S7 · 联调

| 项 | 内容 |
|---|---|
| **目标** | 与外部系统一笔打穿，并锁死异常处置口径 |
| **输入** | 联调作战手册 + 真实报文样例 |
| **动作** | ① 前置逐项打勾；② **逐笔用例**；③ 异常预案就位；④ **首笔原始报文留证** |
| **输出物** | 联调作战手册 + 联调记录 |
| **准出判据** | **一笔真实小额打穿**（真实扣款 + 业务生效 + 落库） |

**关键做法**

1. **作战手册要素**：前置清单 / 逐笔用例 / **异常处置预案** / 物料清单 / 收尾项
2. 🔴 **首笔报文即答案**：真实报文的原始 body 会落库 ⇒ **别提前问对方一堆参数**
3. 🔴 **联调期不碰真实资金**：预置额度/券覆盖全部测试对象（使其走"纯内部路径"必成）

### S8 · 上线与值守

| 项 | 内容 |
|---|---|
| **目标** | 上线有据可依、出事能秒级回退 |
| **输入** | 上线检查清单（提前版） |
| **动作** | ① 上线前逐项打勾；② 上线后逐项验证；③ 值班 + 上报路径；④ 一次性报备客户 |
| **输出物** | 上线检查清单（含状态）+ 回滚三级 + 报备项 |
| **准出判据** | 清单**全过**；**任一未过即不放量** |

**上线检查清单推荐结构（A~G 七段）**

| 段 | 内容 |
|---|---|
| **A 代码与构建** | 缺陷闭环 / 关键功能 / 开关状态 / 产物可追溯 |
| **B 数据与配置** | 🔴 **硬要求集中区**（预算口径 / 倍率上限 / 唯一性约束 / **启动参数不得带 mock 覆盖**） |
| **C 部署与入口** | 🔴 **只暴露必要路径** / 多节点都要改 / 服务不对公网 / 备份落地 |
| **D 外部对接** | 对方已切换 + 一笔打穿 + 口径核对 |
| **E 值守与回滚** | 回滚三级 + 值守人 + 监控关键字 |
| **F 上线后验证** | 首笔 / **金额守恒** / 附加动作 / **幂等** / 凭证健康 |
| **G 一次性报备** | 退款口径 / **边界保护说明** |

**回滚三级（触发即执行，不必等批准）**

| 级 | 动作 | 触发 | 影响面 |
|---|---|---|---|
| **1 开关回退** | 关某段功能开关 / 停某条规则 | 单段异常 | 局部功能，主链路不受影响 |
| **2 摘除入口** | 下线入口配置并重载网关 ⇒ 外部改回原流程 | 大面积失败 | **回到原系统流程，用户照常使用** |
| **3 服务回退** | 换回上一版本产物 + 重启 | 严重缺陷 | 短暂中断 |

> 🔴 **铁律**：任何一级回滚**不重启数据库、不丢数据**；回滚后**逐项补验证 + 记台账**。

### S9 · 运营期

| 项 | 内容 |
|---|---|
| **目标** | 系统可无人值守运行；异常可发现、可追溯、可恢复 |
| **输入** | 运维台账 + 备份方案 |
| **动作** | ① 每日巡检；② 每日备份 + 跨机副本；③ 定期增量同步；④ 定期复盘 |
| **输出物** | 生产运维台账（逐日一行）+ 复盘记 |
| **准出判据** | 巡检**每日有记录**；备份**可恢复**（演练过） |

**运维四件套**

| # | 件 | 做法 |
|---|---|---|
| 1 | **每日巡检** | 服务存活 + 重启次数不增长 / 端口只听回环 / 日志无持续鉴权失败 / 备份日志今日 OK / 业务流水正常 / 磁盘 / 对方接口可达 |
| 2 | **备份四层** | 脚本（权限收紧、零密钥）＋ 定时任务 ＋ **恢复演练**（数据与属主双对拍）＋ **跨机副本** |
| 3 | **回滚两层** | **版本库**（管代码与文档）＋ **每日快照**（管版本库之外，**排除全部密钥**） |
| 4 | **台账三件** | 生产运维台账 / 原系统改动台账 / 事故与教训台账 |

> 🔴 **备份铁律**：若备份含**个人隐私数据**（手机号等）⇒ **绝不下载出客户环境**；异地容灾须客户指定位置。
> 🔴 **数据"陈旧"没有告警** —— 本次实践中，一份基础数据是**一次性快照**，缺口随时间扩大却无人察觉，直到业务失败才暴露。⇒ **必须定期主动核对数据覆盖率。**

## 三、十条工程纪律

| # | 纪律 | 说明 |
|---|---|---|
| 1 | 🔴 **台账只增不删（append-only）** | 日志/台账/复盘记**只追加**；状态型文件的**状态列**可更新，但**不得删除原计划文字**；**写错 ⇒ 新增"更正"行** |
| 2 | 🔴 **最小触碰生产** | 生产库**只读**；被对接系统源码**只读**；只做本模块，不牵连其他 |
| 3 | 🔴 **证据驱动** | 结论必须带**真实文件路径 + 行号**；找不到写"**未找到**"；**禁止推测**；不采信自述 |
| 4 | 🔴 **先模拟再生产** | 要验生产行为 ⇒ 自建 mock（同路径/同报文/可控失败）⇒ **零触碰生产** |
| 5 | 🔴 **逐步验收** | 一次一个 Step；**计数/状态类期望值先声明前提** |
| 6 | 🔴 **凭证管理** | 口令/密钥**不进命令行、不进版本库、不进聊天、不进快照**；落**权限收紧的配置文件**；**私钥不出本机** |
| 7 | 🔴 **改动留痕** | 动被对接系统（配置/服务器/开放平台配置）⇒ 先登台账：**计划 → 备份 → 执行 → 补验证** |
| 8 | 🔴 **命名与署名** | 项目名、模块名**统一口径**；文档署名固定 |
| 9 | 🔴 **对外沟通只给要点** | 目的 → 要点 → 注意；**不给逐字话术**（除非明确要）；首条用**口语化短句**，不上来发长文 |
| 10 | 🔴 **非必要不对外提问** | 能从报文/源码得到的答案，不占用对方时间 |

## 六、常见风险与对策（五类）

### 6.1 🔴 "本地全绿、生产失效"型（最高频，本项目 5 次）

| # | 现象 | 根因 | 对策 |
|---|---|---|---|
| 1 | 有效期字段口径不符 | 双口径未对齐 | 拿对方源码逐字核对 |
| 2 | 读错返回字段名（如 `status` vs `trade_status`） | 字段名想当然 | 同上 + 全项目检索取值点 |
| 3 | 唯一性约束未知（单号"前置即占用"） | 未核对单号生命周期 | 核对方"先插单再调"逻辑 |
| 4 | **签名只签了部分字段**（报文 30+ 字段只签 6 个） | 照抄了"恰好相等"的旧方法 | 核对方验签中间件 |
| 5 | **空值不参与签名** | 语言间隐式转换差异 | 按对方源码复刻值转换规则 |

> 🔴 **共同特征**：**都在 mock 未开验签时"全绿"**。
> 🔴 **对策**：① 出站接口动手前核「状态机/唯一性/返回键名/签名口径」；② **mock 照对方口径实现验签并默认开**；③ 把签名做成**可回归的自动化断言**（不再靠"跑通一次算数"）。

### 6.2 🟡 环境与工具坑

| # | 坑 | 对策 |
|---|---|---|
| 1 | 远程执行命令卡住 | 单条命令加"不读标准输入"参数；**"卡住 ≠ 没执行"**（先看状态，别盲目重跑） |
| 2 | 需要交互终端时带了"不读标准输入"参数 | 去掉该参数；**判据＝提示符变成远端主机名** |
| 3 | 终端吞引号/抢管道 | 含特殊字符的命令 ⇒ **先进远端 shell 再贴** |
| 4 | 脚本编码 | 含中文的脚本用 UTF-8 BOM；生成文档走固定工具链 |
| 5 | 改了 mock/脚本没生效 | **重启进程**（脚本引擎不热重载）⇒ "文件是新的、跑的是旧的" |
| 6 | 改了代码没重启服务 | 跑的是**旧 class** ⇒ **改完先重启再跑用例** |

### 6.3 🔴 判据类坑

| # | 坑 | 对策 |
|---|---|---|
| 1 | 用**文件大小**判备份完整性 | 改用**计数/表数对拍** |
| 2 | 判据看错字段 | 业务文案通常在 `data.*`，而非外层 `msg` ⇒ **判据一律看 `data.*`** |
| 3 | 计数类期望值不声明前提 | 必出"数字对不上的假问题" ⇒ **先声明前提** |
| 4 | "没有日志 = 没执行" | 日志可能在**另一节点**；也可能级别不够（`debug` 生产看不见） |

### 6.4 🔴 部署类坑

| # | 坑 | 对策 |
|---|---|---|
| 1 | **只改一台配置** | 多节点 ⇒ 必须一致 |
| 2 | 只从一台自测 | 逐节点验证须"强制解析到本机" |
| 3 | 进程托管方式切换丢环境变量 | 用**独立环境变量文件**（权限收紧）供给；**服务定义不含密钥** |
| 4 | 本地实例占用产物文件 | 打包前先停本地进程 |

### 6.5 🔴 数据类坑

| # | 坑 | 对策 |
|---|---|---|
| 1 | **数据同步是一次性快照** | 定期核对覆盖率；推动源方给**增量/实时接口**；缺口期先用**手工重导**兜底 |
| 2 | 增量导入与上次窗口重叠 | 用**幂等写入**；**总数守恒**即为"没丢数据"的证明 |
| 3 | 导出格式踩坑（列名/引号/反引号） | 用 SQL 直接拼 `INSERT` 文本（**绕开导出向导的格式坑**） |
